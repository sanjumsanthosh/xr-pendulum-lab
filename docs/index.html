one core, three consumers

The physics doesn't get reimplemented

The same header compiles into the native test binary and into the WASM module the browser runs. There is no second implementation to drift out of sync.

// pendulum.hpp — semi-implicit Euler, one step
const double acceleration =
  -gravity * std::sin(state.angleRadians) / length;
state.angularVelocity += acceleration * dt;
state.angleRadians    += state.angularVelocity * dt;

// small-angle theory, for comparison
T = 2.0 * PI * std::sqrt(length / gravity);
  • Sub-frame crossings. The period is interpolated between the two samples straddling a zero-crossing, so it isn't quantised to the frame rate.
  • Measurement, not assertion. The HUD shows analytic period next to the measured one — the gap is the interesting part.
  • Warnings are errors. The native suite compiles with -Wall -Wextra -Werror.
  • Reset is clean. Changing length or gravity reinitialises the lab instead of leaving stale state.

run it

Two toolchains, one command each

# needs emscripten (emcc) and a C++17 compiler
$ npm install
$ npm run dev      # builds wasm, then vite
$ npm test         # native + wasm suites

# CXX=clang++ to pick a compiler
